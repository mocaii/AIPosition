# 当前架构：Git 内容源与静态网站

本方案取代早期 CMS / PostgreSQL 设计。代码只使用一个运行时依赖 yaml，开发测试使用 Playwright。

```text
content/*.yaml
    ↓ 解析、校验、过滤未发布条目
scripts/build.mjs
    ├── 每岗位 / 资料 / 技能的 HTML 页面
    ├── 公开数据与搜索索引 assets/data.json
    └── 浏览器交互、CSS、图标
dist/ → GitHub Pages
```

内容模型和校验集中在 `scripts/content.mjs`，发布投影删除未发布条目与关联。浏览器不接触草稿。校验是本地和 CI 的发布门槛；运行时不需要服务器或 API。

`scripts/build.mjs` 负责内容渲染和路径生成；所有内容文本进行 HTML 转义。链接限定 HTTP(S)，文件路径和 slug 有格式约束。图谱仅使用公开岗位的真实技能关联。

`src/assets/app.js` 渐进增强服务器预生成的页面：组合筛选、URL 状态、跨类型搜索、桌面岗位抽屉、局部图谱。手机点击岗位链接直接打开静态详情。关闭 JavaScript 时仍可通过普通链接阅读。

`src/assets/search.js` 包含可测试的中英文搜索和筛选逻辑；当前规模不需要搜索服务器。公开索引包含完整公开条目，增长到明显影响下载和搜索性能时，可再按页面分包或引入专门索引。

## 远程仓库与公开发布边界

- 本项目连接 GitHub 仓库 `mocaii/AIPosition`，通过默认分支工作流发布。
- 网站仓库地址从显式环境变量、配置、GitHub Actions 或本地 origin 获取，只接受合法 GitHub 仓库地址。
- 未配置仓库时跳转贡献说明页，不伪造 Issue、编辑或发布成功。
- 默认分支发布，PR 仅构建校验和提供 artifact。
- 生产站点可以部署到任何静态托管；GitHub Pages 工作流是内置的首选路径。

## 自动链接检查

仅检查已发布的学习资料；请求设超时和并发上限，逐次验证重定向目标。拒绝私网、回环、云元数据、非 HTTP(S) 协议和非标准端口；DNS 解析结果固定用于请求，减少重绑定风险。

本轮不抓取或执行页面脚本，不对资料内容做自动质量认证。报告提交到仓库维护 Issue，人工判断是否需要修订条目。

## 重要限制

- slug 改动没有自动生成重定向，维护者应保持 URL 稳定。
- 草稿控制的是网站发布；若 Git 仓库公开，草稿文件仍可被仓库访客读取，不能存秘密。
- 抓取检查不等于用户浏览器的可达性，也不验证付费章节或课程许可。
- PR 的独立在线预览地址未接入；自动化提供可下载构建包。
- `research/` 是历史快照；网站以 `content/` 为唯一内容源，保留的 Python 研究生成脚本不参与网站发布。
